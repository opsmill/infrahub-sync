# Contract: what this plan needs from the prerequisite

The prerequisite is two capabilities of INFP-655. They are not built by this plan. This file
states what the worker of a scheduled run calls, so that the tasks that depend on it can be
written when the prerequisite exists. The prerequisite may deliver the same capabilities in
another form; the tasks then follow that form.

All five operations run in the worker, with the destination credentials the worker already holds.

| Operation | Input | Result | Used for |
| --- | --- | --- | --- |
| Create a branch for a run | A run, a branch name | The branch exists in Infrahub, created from the default branch, with no synchronization to Git. The run's verify and apply steps write to it. | FR-001 |
| Open a proposed change | A run that finished its write to such a branch, a title, a description | The identifier of an open proposed change from the branch to the default branch | FR-001 |
| Read a proposed change | An identifier | One of `open`, `approved`, `merged`, `closed`, `missing` | FR-021 |
| Close a proposed change | An identifier, a comment | The proposed change is closed and holds the comment | FR-020 |
| Delete a branch | A branch name that Infrahub Sync created | The branch no longer exists. A branch that is already missing is not an error. | FR-020 |

## Requirements on the prerequisite

1. **Plan before the branch exists.** A run plans against the default branch, and the branch is
   created only when the plan holds at least one operation (FR-022). If the prerequisite creates
   the branch before the plan, this plan uses the fallback of research R11: delete the branch
   when the plan holds no operation.
2. **`approved` means a person approved.** The state is `approved` when at least one person
   approved the proposed change in Infrahub and it is still open.
3. **Failures are typed.** Each operation fails with a cause that the run's failure record can
   hold (ADR 0021), without text that may hold a credential.
4. **Repeating is safe.** Creating a branch that the same run already created, and closing a
   proposed change that is already closed, succeed.

## What this plan adds on top

- The branch name: `sync/<schedule name>-<YYYYMMDD>-<6 hexadecimal characters>`, generated by the
  service when it starts the run.
- The title of the proposed change: `Scheduled sync <schedule name> <start time in UTC>`.
- The description: the run identifier, the configuration and version, and the plan's counts of
  created, updated and left-out records. No source data.
- The comment on a replaced proposed change: `Replaced by <identifier of the new proposed
  change> (run <run_id>)`.
- The order of the steps, in research R11.

## Tests before the prerequisite exists

The service side is tested with a worker result that a test writes. No test of this plan calls
Infrahub for a branch or a proposed change until the prerequisite exists.
