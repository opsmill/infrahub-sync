## Executive Summary

The spec follows the brief closely and the plan is grounded in probes of the installed SDK (request URL shape,
error type, header loss on next pages, retry handler switch). The main gap is the most common real-world failure:
a wrong or expired client secret, or no usable credential in `default` mode, fails during token acquisition, before
any HTTP status exists, and the plan does not map it to a clear error. Smaller items: the `members` key without a
`reference`, `asyncio.run` inside a running event loop, a test seam for retry waits, and a `ty` warning that the
brief's import pattern produces when the SDK is installed. All are resolvable in the spec and plan; none needs a
change of direction.
