# Critique: Convert a v1 or v2 configuration and prove the first V3 plan

**Date**: 2026-10-22 | **Spec**: [spec.md](../spec.md) | **Plan**: [plan.md](../plan.md)

## Executive summary

The spec and plan solve a real, bounded problem with a small design: one pure module, one thin
command, one nightly suite. Two findings must be fixed before tasks:

- the environment-first rule lets the input file name any variable, so the command could read a
  credential and print it or write it into the package (E1)
- an address can carry a user name and password, which the command would print and write (E2)

Both are fixed by narrowing what the command reads and refuses, without changing any user story.

**Verdict: ⚠️ PROCEED WITH UPDATES.** The fixes were applied to `spec.md` and `research.md` in
the same phase.

### 3e. Success measurement

## Engineering lens

### 4a. Architecture

- The pure conversion module and the thin command follow the existing split between
  `configuration/` and `cli.py`. The tables are constants pinned by tests. No finding.

### 4b. Failure modes

- E3 (💡): FR-003 says "without a terminal" without naming the stream. A command piped into a
  log has a terminal on standard input but not on standard output. Suggestion: the confirmation
  depends on standard input being a terminal. **Applied** to `research.md` R8.

### 4c. Security and privacy

- E1 (🎯): research R2 and R3 read the variable that a `${VARIABLE}` placeholder names, and the
  variables that a `genericrestapi` `url_env_vars` setting names. Both come from the input file,
  so `url: ${NETBOX_TOKEN}` or `url_env_vars: [INFRAHUB_SYNC_API_TOKEN]` makes the command read a
  credential, print it as an address, and write it into the package. This breaks FR-007 and
  constitution VI. Suggestion: the command reads only the fixed variable names of the R2 table
  that are not credentials. A placeholder or an `*_env_vars` entry that names any other variable
  is not read; the report says so, and the address must come from the file or a flag.
  **Applied** to `spec.md` (FR-029, edge case) and `research.md` (R2, R3).
- E2 (🎯): an address may contain a user name and password (`https://user:secret@netbox`). The
  command would print it in the report and write it into the package, which a registration
  stores. Suggestion: refuse an address with user information, name the setting, and do not
  print the value. **Applied** to `spec.md` (FR-030) and `research.md` (R9).

### 4d. Performance

- One file, no network. No finding.

### 4e. Testing

- E4 (💡): the gate's left-out and problem checks wait for spec 009. The plan already makes the
  suite stop rather than pass. Suggestion: name this in tasks as a blocked task with its
  dependency. To apply in tasks.

### 4f. Operational readiness

- E5 (💡): `COMPOSE_WORKER_CREDENTIAL_VARIABLES` describes the Compose file shipped with the same
  version as the CLI. A customer with an older or edited Compose file can get a wrong warning.
  Suggestion: word the warning as "the Compose file shipped with this version does not pass …".
  **Applied** to `research.md` R5.

### 4g. Dependencies

- Spec 009, the Compose worker variables, and the unchanged-plan fixes are named with what
  happens while they are missing. No new finding.

## Cross-lens insights

- X1 (💡): FR-011 lets a v2 variable win over the file, as v2 did. For `genericrestapi` the
  default names are `URL` and `ADDRESS`, which other software may set. With `--yes` in a script,
  no one reads the report. Suggestion: keep v2's order, and make the report line for a value
  taken from `URL` or `ADDRESS` a warning. **Applied** to `research.md` R2.
