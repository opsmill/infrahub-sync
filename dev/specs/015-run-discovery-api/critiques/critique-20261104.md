# Critique: Discoverable runs, configurations and versions

**Date**: 2026-11-04
**Inputs**: [spec.md](../spec.md), [plan.md](../plan.md), [research.md](../research.md),
[contracts/](../contracts/), constitution (`docs/docs/development/constitution.md`).

## Executive summary

The spec answers a documented gap: `product/path-to-3.0.md` lists the missing run list for
the API, the CLI and the web UI, and says that no card covers it. The plan reuses the
store's existing migration mechanism, adds no dependency and does not touch the vendored
Prefect code. One finding conflicts with the constitution: `runs cancel` adds a mutating CLI
command without an explicit confirmation. A second finding concerns the Prefect tags. The
plan overwrites a flow run's tags with a fixed list, so tags that an operator added to the
deployment in Prefect would be lost. Both have clear fixes.

**Verdict**: ⚠️ PROCEED WITH UPDATES. The fixes for the findings below are applied to the
plan and contracts.

## Product lens

### 3a. Problem validation

- The need is documented in the product records: `path-to-3.0.md` lines 50, 60, 217 and 250,
  and the capability outline's `runs list` and `GET /runs`. The owner confirmed the scope in
  an interview on 2026-11-04.
- The scope is bounded: filters are limited to configuration and version, and actor, phase
  and date filters are deferred.

### 3b. User value

- US1 and US2 together deliver SC-001. US3 to US5 each ship on their own.
- **P1 (💡)**: the spec removes `branch` from the run list because the run does not store it.
  An operator who has several runs of one version on different branches cannot tell them
  apart in the list without opening each plan. The spec's Assumptions section records this.
  Keep it deferred, but name it as the first follow-up.

### 3c. Alternatives

- Offset paging would be simpler, but it breaks FR-004 when runs are created between page
  reads. Keyset paging is justified.

### 3d. Edge cases and user experience

- **P2 (💡)**: name resolution tries the value as an identifier first. A value that is both a
  `config_id` and another configuration's name silently resolves to the identifier. This
  behavior is safe and predictable, but the CLI reference should state it.
- The breaking change to the list responses affects only the bundled client and CLI, because
  the web UI does not exist yet. A changelog fragment of type `changed` is needed.

### 3e. Success measurement

- SC-001 to SC-005 can each be verified, and the quickstart covers every one of them.

## Engineering lens

### 4a. Architecture

- A single `paging.py` module shared by three routes avoids having three cursor formats.
- List items reuse the bounded emitted run resource, so FR-002 holds without a second model.

### 4b. Failure modes

- **E1 (💡)**: keyset ordering compares `started_at` as text. The only writer
  (`infrahub_sync/service/service.py:149`, `:184`) uses `datetime.now(timezone.utc)`, but the
  service's clock can be injected (`service.py:129`). A clock that is not in UTC would
  produce text that sorts in the wrong order.
  - **Fix**: convert `started_at` to UTC when the store inserts a run.
  - **Test**: insert a run whose start time is not in UTC and check its position in the list.
- **E2 (🎯)**: Prefect's `update_flow_run(tags=...)` replaces the existing tags. The plan writes
  the deployment's tags from `SERVICE_DEFINITION`. Tags that an operator adds to the
  deployment in Prefect would therefore be removed from each flow run.
  - **Fix**: read the flow run's current tags and write their union with the run tags.
  - **Cost**: one extra read, which runs in the same best-effort block as the title update.
- A failure to set the tags is logged and swallowed, the same way the title is handled today
  (FR-012).

### 4c. Security

- **E3 (🎯, constitution)**: "New mutating behavior MUST ship behind explicit flags." The
  `runs cancel` command can end a write with an `ambiguous` outcome and set
  `reconciliation_required`.
  - **Fix**: require `--yes`, or a confirmation prompt when the command runs interactively.
- Every authenticated principal can list all runs. This exposes no new data, because any
  principal can already read any run by its identifier.
- `/me` returns no secret values. Tags carry only identifiers.

### 4d. Performance

- The two composite indexes cover list and latest-run queries. Version references are fetched
  with one query per page.
- The configuration-name backfill at start-up runs once per configuration whose name is
  `NULL`.

### 4e. Testing

- Cursor stability under concurrent inserts is tested with a fixture of 120 runs, with 10
  more inserted between page reads.
- The migration steps need both SQLite and PostgreSQL coverage
  (`tests/product_store/test_postgresql_isolation.py`).

### 4f. Operational readiness

- Rollback is safe: an earlier release ignores the new nullable columns and indexes, and its
  insert statements omit them.
- There are no numbered migrations to revert.

### 4g. Dependencies

- The plan adds no dependency. The vendored Prefect Extras code stays byte-identical.

## Cross-lens insights

- **X1**: `runs cancel` must have a confirmation step (E3). This also prevents an operator from
  cancelling a write by mistake and leaving it with an `ambiguous` outcome.
