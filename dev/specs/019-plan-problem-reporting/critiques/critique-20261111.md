# Critique: Plan problem reporting

**Date**: 2026-11-11

**Reviewed**: [spec.md](../spec.md), [plan.md](../plan.md), [research.md](../research.md),
[data-model.md](../data-model.md), [contracts/](../contracts/), constitution 1.0.4

**Verdict**: PROCEED WITH UPDATES. One must-address item was found and fixed in the plan
artifacts before tasks were generated.

## Executive summary

The spec keeps old 009's requirements and states which ones the current code already delivers.
The plan builds on the spec 017 failure record, the plan format 3 reader and the existing
`configs validate` opt-in instead of adding parallel structures. One design statement was wrong
in code: research R11 assumed a stopped `sync` run held no write admission. It holds one from its
creation (`infrahub_sync/service/service.py:281`), so the confirmed apply that FR-012 requires
would have been refused with `run-execution-conflict`. R11 now appends that apply under the
`sync` run's existing admission, with tests for the admitted and the refused cases.

## Product lens

### Problem validation

- The problem is backed by dated evidence: five configuration versions for five problems on
  2026-10-05 (#369), and issues #370, #371, #374, #166. No finding.

### User value

- P1 (recommendation, applied in the spec): a stopped `sync` run must be appliable once, or the
  team loses the plan it reviewed. FR-023 now states that the one confirmed apply of a stopped
  `sync` is admitted.
- P2 (recommendation, not applied): User Stories 5 and 6 are P2. They are testing-release
  blockers on the release scope page, but each has a workaround (run a plan and read its
  failure). The priority stays; tasks keep them in the same delivery.

### Alternatives

- Decision 8 removes three CLI commands in favor of `runs plan` options. Fewer commands, same
  information. No finding.

### Edge cases and user experience

- P3 (recommendation, applied): format 3 plans saved before the upgrade are refused at apply
  (research R9). Runs in progress at upgrade need a new plan. The tasks add a changelog line and a
  note in the upgrade documentation.

### Success measurement

- SC-001 to SC-011 are testable. SC-001 and SC-008 need the live `from-netbox` tier. No finding.

## Engineering lens

### Architecture soundness

- E1 (must-address, fixed): see the summary. Fixed in research R11, data-model.md (state table),
  plan.md (open risks, Complexity Tracking) and spec FR-023.
- E2 (recommendation, applied): the CLI prints the stopped `sync` hint from `results.failure`, not
  from a `<stage>_failure` record; `_echo_failure_record` reads only the latter
  (`infrahub_sync/cli.py:848-866`). contracts/cli.md now says which field the CLI reads.

### Failure modes

- E3 (recommendation, applied): R12 did not say how a source adapter's refused token or
  unreachable address is told apart without reading error text. plan.md open risks now require a
  per-adapter table keyed on exception type and HTTP status code only, with `internal_error` as
  the fallback.

### Security and privacy

- E4 (no change): `infrahub_message` is Infrahub's text about a write that held only source data.
  Recorded under ADR 0021 and the constitution's principle VI in Complexity Tracking.
- The masking pass stays unchanged (decision 3). The tests with a 5-character credential and a
  credential with `"`, `\` and `,` are required by SC-007.

### Performance and scalability

- E5 (recommendation, not applied): the problem pass and the report add memory proportional to
  the number of problems. At tier M this is small. The time is measured before and after (R19);
  no target is set because the spec sets none.

### Testing strategy

- Planned tests cover each problem type, each failure type, each refusal, the replan after a
  stopped apply, and the credential absence. No finding.

### Operational readiness

- E6 (recommendation, applied in tasks): the new `worker_environments` table is created with
  `CREATE TABLE IF NOT EXISTS`, which a rollback leaves in place unused. The tasks document this.

### Dependencies and integration

- The AD-12 amendment in `infrahub-sync-process` is an external dependency for steps 3 and 4. No
  finding beyond the spec's "Dependencies".

## Questions for the product owner

- Q1: does the 2026-10-17 sign-off on ADR 0020 and 0021 cover the rewritten records? (spec, open
  question 1)
- Q2: refuse the apply of format 3 plans saved before the upgrade? The plan's default is yes
  (spec, open question 2).
