## Executive Summary

The spec solves a real, observed gap: issue #421 shows that no deployment from the image can use the web interface.
The scope is small, and the out-of-scope list is explicit. The plan reuses the existing Sync API application and adds
no Python dependency.

Two engineering problems block implementation as planned:

- **E1. The liveness reconciler stops.** Starlette does not run a mounted application's lifespan. `create_app()`
  starts the run liveness reconciler in its lifespan, so mounting it at `/api` stops that loop with no error. This was
  confirmed with a test against Starlette 1.9.0 and FastAPI 0.141.1.
- **E3. Any web page can use the anonymous principal.** The anonymous access setting gives every request without an
  `Authorization` header the named principal. Through DNS rebinding, a web page the operator visits can send
  same-origin requests to `127.0.0.1:8001`, including `apply`. The default publication on loopback does not protect
  against this.

Both have contained fixes. The other findings improve testability, operations and documentation.

| ID | Severity | Finding | Suggestion |

### Security & Privacy

| ID | Severity | Finding | Suggestion |
|----|----------|---------|------------|
| E3 | 🎯 | The browser threat model for anonymous access is missing. When the setting is on, the Sync API grants the principal to any request without `Authorization`. Cross-site requests are blocked today by accident, not by design: writes need the `Idempotency-Key` header, so the browser sends a preflight request, and the Sync API answers no CORS. But **DNS rebinding** makes an attacker's page same-origin with `127.0.0.1:8001`, so no preflight is needed and the page can call `apply`. The `POST /configs/{id}/versions/{v}/validate` route needs no custom header, so a plain cross-site form can trigger it. | Add requirements to the spec and plan: (1) when the anonymous access setting is set, a request without `Authorization` acts as the anonymous principal only if its `Host` header names an allowed host. The allowed hosts come from a new setting that defaults to `localhost` and `127.0.0.1`, so a compose deployment on loopback needs no extra step and SC-001 still holds. Other requests get 401. (2) Such a request with an `Origin` header that differs from the Sync API's own origin is refused with 403. Add tests for both. |
| E5 | 💡 | The web interface can be loaded in a frame on another site. With the anonymous principal, a framing page could trick a person into selecting **Apply** (clickjacking). | Send `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'` and `X-Content-Type-Options: nosniff` on web interface responses. Do not apply a script policy to `/api/docs`, which loads Swagger UI from a CDN. A full script policy would also need a hash for the inline theme script in `frontend/index.html:21`. |
| E6 | 💡 | A stored token in `localStorage` can be read by any script that runs on the page. React escapes rendered data, but plan contents come from source and destination systems. | Keep the user's decision. Add a `script-src 'self' 'sha256-<theme script>'` policy to the `index.html` response, so that injected inline script cannot run. Low cost, and it protects the stored token. |
