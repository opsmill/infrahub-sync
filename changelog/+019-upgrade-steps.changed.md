Moving to this release changes the upgrade steps, as described in "Changes when you move to the release that reports plan problems" in the day-2 operations guide. Apply the worker's Prefect deployment again before or together with the Sync API of this release: an apply of a plan that leaves out records sends the new `confirm_left_out` parameter to the worker. The Compose deployment does this through its `sync-bootstrap` job on `docker compose up -d --wait`; other deployments run `python -m infrahub_sync.service.deploy`. Each worker restart adds a row to the new `worker_environments` table, and the rows of earlier worker processes stay. A source adapter that reads only the records changed since the last run (a custom adapter that defines `safe_cursor_before_load`; no bundled adapter does) does not check those records for problems.
