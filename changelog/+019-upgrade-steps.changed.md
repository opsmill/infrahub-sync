Moving to this release changes the upgrade steps, as described in "Changes when you move to the release that reports plan problems" in the day-2 operations guide. Apply the worker's Prefect deployment again before or together with the Sync API of this release: an apply of a plan that leaves out records sends the new `confirm_left_out` parameter to the worker. The Compose deployment does this through its `sync-bootstrap` job on `docker compose up -d --wait`; other deployments run `python -m infrahub_sync.service.deploy`. Each worker restart adds a row to the new `worker_environments` table, and the rows of earlier worker processes stay. A custom source adapter that reads only the records changed since the last run (it defines `safe_cursor_before_load`; no bundled adapter does) must now implement `list_changed_records`, which returns the raw changed records, so that those records are checked for problems as in a full read; without it, the adapter reads every record. A source snapshot saved by an earlier release causes one full read of each kind.
