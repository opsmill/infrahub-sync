An interrupted apply or `sync` can now continue on the same run: `verify` reports, for up to 2,000 creates and updates that may have reached the destination, whether the node matches the plan, differs from it or is missing, and how many it left out, and `runs resume RUN_ID --expected-checksum CHECKSUM` (`POST /runs/{run_id}/resume`) applies the rest of the saved plan from the last saved position. `runs show` prints how far the write got, whether the run can be resumed, and the committed, uncertain and not-reached operations of each kind. When the Sync API requires approval, `approve` now also accepts an interrupted run that can be resumed, so a `sync` run or an apply interrupted before approval was required can be resumed. A `sync` run whose worker was killed before it saved its plan wrote nothing, so it is reported as not resumable, and `runs resume` refuses it and says to start a new `plan` or `sync` run.
