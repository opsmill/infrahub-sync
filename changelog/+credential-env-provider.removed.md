The `env` credential provider, the `credentials` block of a configuration package and `$credential` references are removed, and the Sync API and its worker no longer read `INFRAHUB_SYNC_CREDENTIAL_*` variables. Registration and validation refuse a package that holds a `credentials` key, empty or not, or a `$credential` reference. A version that was registered with a `$credential` reference is refused with `422 credential-format-removed` when a plan, a sync, a verify, an apply, an approval or a resume of it starts, when a schedule that names it is created or changed, and at each start of a schedule that already names it; its saved plans cannot be approved or applied, and the version, its runs, their results, artifacts and logs can still be viewed. A version that was registered with no secret keeps its checksum and runs as before. To upgrade, create a stored credential for each secret with `infrahub-sync credentials create`, replace the `credentials` block and the references with `credential: <name>` in each adapter block, add the package as a new version with `infrahub-sync configs version`, point each schedule to the new version with `infrahub-sync schedules change --version`, and plan again. `configs convert` now writes `credential: <name>` and lists the credentials to create. Workers no longer publish the names of their credential variables, and `configs validate --branch` no longer reports `credential-not-set-in-worker` or `worker-environment-unknown`. The findings `malformed-credential-reference`, `unknown-credential-provider`, `unknown-credential-reference` and `credential-path-not-declared` are removed. The direct Prefect flow, which runs a `config.yml` outside a registered package, still reads adapter variables such as `NETBOX_TOKEN` from the environment of the serving process.
