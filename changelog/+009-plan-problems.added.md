One plan now lists every problem in the source data, of nine named types. The plan leaves out each record with a problem and each record that depends on one through a required relationship, keeps a record that refers to a left-out record only through an optional relationship without that relationship, and saves the list in plan format 4. Two or more Infrahub objects of one kind with the same configured identity are the problem `destination_identity_ambiguous`, which names the kind, the identity and the Infrahub IDs of the objects; the plan leaves out the source record with that identity and plans no create, update or delete for that identity, where before it kept the last object it read. A transform that fails for one source record, for example a mapping of interface modes without `q-in-q`, is the problem `transform_failed`, which names the field and the transform's position (`transforms[0]`) but not the source value; before, it failed the whole plan. `infrahub-sync runs problems`, `runs left-out` and `runs kept` list the entries, and the Sync API returns them from `GET /runs/{run_id}/plan/problems`, `/plan/left-out` and `/plan/kept`. Plans saved by earlier releases must be planned again before apply.
