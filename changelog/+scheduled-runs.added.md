Add schedules: the `infrahub-sync schedules` commands and the `/schedules` routes of the Sync API create, list, show, change, pause, resume, delete and take over a schedule that starts a `sync` run of one configuration version on a cron cadence. Runs record their trigger type and schedule, and `runs list` and `events` filter on them. By default each scheduled run writes to a new Infrahub branch and opens a proposed change for review, and the next run closes the earlier proposed change and deletes its branch. With `--write-to-default-branch` on `schedules create`, or `--write-to-default-branch` and `--write-to-branch-review` on `schedules change`, a schedule writes to the branch that a `sync` of the configuration writes to; a Sync API that requires an approved plan refuses it and stops such a schedule. A start whose Infrahub destination does not answer yet waits and checks again every minute, within the schedule's late-start duration, with no run and no failure recorded. A product database that an earlier build created cannot be used with this version: the Sync service refuses to start on it, because there is no in-place upgrade. Replace the product database before you upgrade.
