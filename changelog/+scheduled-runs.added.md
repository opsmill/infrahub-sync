Add schedules: the `infrahub-sync schedules` commands and the `/schedules` routes of the Sync API create, list, show, change, pause, resume, delete and take over a schedule that starts a `sync` run of one configuration version on a cron cadence. Runs record their trigger type and schedule, and `runs list` and `events` filter on them. By default a scheduled run writes to a new Infrahub branch; when its plan has changes it opens a proposed change for review, and when it has none it deletes its branch. A later run that opens its own proposed change closes the earlier proposed change that no one approved, merged or closed, and deletes its branch; while an earlier proposed change is approved and open, a start does not run. With `--write-to-default-branch` on `schedules create` or `schedules change`, a schedule writes to the branch that a `sync` of the configuration writes to, with no proposed change; `--write-to-branch-review` on `schedules change` returns it to branch review. A Sync API that requires an approved plan refuses `--write-to-default-branch` and stops a schedule that writes to that branch. A scheduled run acts as the schedule's owner, the account that created it or the administrator who took it over; a start of a schedule whose owner's account is disabled or deleted creates no run and stops the schedule. A start whose Infrahub destination does not answer yet waits and checks again every minute, within the schedule's late-start duration, with no run and no failure recorded. A product database that an earlier build created cannot be used with this version: the Sync service refuses to start on it, because there is no in-place upgrade. Replace the product database before you upgrade.
