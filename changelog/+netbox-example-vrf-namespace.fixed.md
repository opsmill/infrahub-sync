The NetBox example now maps each NetBox VRF to an Infrahub IP namespace and identifies prefixes and IP addresses by that namespace, so prefixes that overlap across VRFs with distinct names no longer collapse into a single Infrahub object; objects with no VRF — along with a VRF named `default` — go to Infrahub's built-in `default` namespace. The namespace is keyed on the VRF name, so two VRFs sharing a name are refused while the source is loaded rather than merged, and the documentation now carries a configuration recipe that derives the namespace from the NetBox VRF ID instead.
