The NetBox example now maps each NetBox VRF name to an Infrahub IP namespace and identifies prefixes and IP addresses by that namespace, so overlapping values across VRFs with distinct names no longer target a single Infrahub object. See [VRF-derived namespace limitations](https://docs.infrahub.app/sync/migrating-from-netbox-or-nautobot#namespace-mapping-limitations) for source-load errors and mapping guidance. Existing imports keep their old prefixes and addresses in the `default` namespace: adopting the updated example does not move or clean up those old objects. Records that still resolve to `default` match their existing objects there; only records that now resolve to a VRF-named namespace get new objects alongside the old ones.
