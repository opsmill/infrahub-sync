`verify` now runs every check that `apply` runs before its first write, against the destination, and writes nothing. It connects to the destination, so it fails when it cannot reach it. The run records the checks that passed under `results.verification.checks`, and the CLI prints one `check: NAME passed` line for each. Earlier, `verify` checked only the files the plan run saved. `apply` now refuses every run in phase `cancelled` with `run-cancelled`, including a run whose `verify` stage was cancelled while it ran.
