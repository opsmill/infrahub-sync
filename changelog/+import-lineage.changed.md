An import into Infrahub now records the import account, the account behind the API token, as the source of every value it writes, unless the package names a source. The `source` and `owner` settings of an Infrahub destination now name a node as `{kind, name}`, with the kind `CoreAccount`, `CoreAccountGroup`, `CoreRepository` or `CoreReadOnlyRepository`; registration refuses a bare name, so update existing packages. When a named source or owner does not exist, a plan stops before it reads the source system and an apply stops before any write, and the error names the setting, the kind and the name. The owner goes only on values a run creates. Apply refuses a saved plan made with a different import account, and a plan saved by an earlier release, which then needs a new plan. `protect` is off by default: the import no longer marks the values it writes as protected unless the package sets `protect: true`, and values protected earlier keep their protection. `runs plan --detail` shows who last changed each value an update proposes to change, and when, on Infrahub 1.7.0 or later. When Infrahub refuses a plan or an apply with HTTP 403, the run records the missing permission, and `plan`, `sync` and `apply` print it on a `cause:` line. For a missing named node or an import account refusal, they also print what to do next on a `hint:` line. Registration refuses a `source` or `owner` name with leading or trailing whitespace.
