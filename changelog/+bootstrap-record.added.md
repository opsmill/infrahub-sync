The service bootstrap now records, as its last step, the Sync version and the work pool it set up. The Sync API and the worker read that record when they start, before they change anything in the product database. When the record is missing, or names another version or another work pool, they log the version and work pool they found and the ones they expected, and exit with a non-zero status. On Kubernetes, the pods then restart until the bootstrap of their version has completed. The Compose deployment runs the bootstrap first, so the check passes on the first start.
