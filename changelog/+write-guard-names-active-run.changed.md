When a `sync`, `apply` or `runs resume` cannot start its write because another write of the same configuration holds the configuration's write guard, the run's failure record now has the failure type `write_guard_contended` and names that other run in `active_run_id`. The CLI prints `active run: <run_id>` and a hint to check it with `infrahub-sync runs show <run_id>`. When Sync finds no such run, the cause says that the run is not known.
