`infrahub-sync configs validate --branch <name>`, and the `branch` parameter of `POST /configs/{config_id}/versions/{registry_version}/validate`, check a registered configuration against a named Infrahub branch before any run starts. The report names each mapped kind, attribute or relationship the branch schema does not hold; each literal Dropdown value that is not one of the attribute's choices (`destination-dropdown-value-not-in-choices`); each permission the import account lacks to view, create or update a mapped kind, or to look up a named `source` or `owner` (`destination-permission-missing`); a `source` or `owner` that matches no node or more than one node (`destination-lineage-node-not-found`, `destination-lineage-node-ambiguous`); and each `$credential` variable that no live worker holds (`credential-not-set-in-worker`), or a `worker-environment-unknown` warning when no live worker has published its variables. With `--branch`, the command exits 1 when a finding on the printed page is an error. Without a branch, validation is unchanged. Each worker now publishes the names of its set, non-empty credential variables, never their values, to the new `worker_environments` table on each poll; the table is created on start-up and stays unused after a rollback.
