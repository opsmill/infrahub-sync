The Sync API can resume an interrupted write by itself. With `INFRAHUB_SYNC_AUTOMATIC_RESUME=true` (off by default), when Prefect reports the flow run of an `apply`, a `sync` or a resume as crashed, or its worker stops sending heartbeats, the Sync API waits for a live worker, runs `verify` on the run, and resumes it when no operation is reported as `differs`. The check and the resume run as `Sync (automatic resume)`. A run receives at most 3 automatic resumes, and none after one that did not move the progress marker forward. `runs show`, the run page and `GET /runs/{run_id}` (`automatic_resumes`, `automatic_resume_count`) state the cause and, when the Sync API did not resume the run, the reason. Two events record the outcome: `infrahub_sync.run.automatic_resume_started` and `infrahub_sync.run.automatic_resume_not_started`. A person who runs `verify` or `runs resume` while the Sync API waits for a worker takes over.
