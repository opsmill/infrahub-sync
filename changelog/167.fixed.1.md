Missing peer identifiers are now fetched once by ID before an error is raised. Null attribute or required relationship identifiers are rejected during Infrahub loads, creates, and ID scans instead of building a `None`-based identity. Peers with explicitly null optional single-peer relationship identifiers, such as an IP address without a VRF, now resolve instead of raising `PeerIdentifierError`. A prefix or IP address whose VRF cannot be resolved now stops the load with an error instead of matching the global-table record; `--continue-on-error` skips it with a warning during full loads and incremental store insertion. ID scans still stop on the validation error.
