A failed or stopped run now records a structured cause: the failure type, the system it came from, Infrahub's error code, and the node kind, attribute and message of a write that Infrahub rejected. `GET /runs/{run_id}` returns it as `failure`, and `diff`, `sync`, `apply` and `runs show` print it instead of `<stage> failed: <ErrorClass>`. The cause holds no error text, address, header or traceback. A peer that an apply operation refers to and that Infrahub no longer holds, because it was deleted or renamed after the plan, stops the apply with the failure type `destination_peer_missing`, which names the peer's kind and the operation; a peer that matches more than one Infrahub object gives `destination_peer_ambiguous`.
