Every Sync API route moved under `/api`, including `/version`, `/status`, `/docs` and `/openapi.json`: for example `GET /runs` is now `GET /api/runs`. No Sync API route answers at its earlier address: a client that does not accept HTML receives a "not found" error that states that the Sync API is served under `/api`, and a browser receives the web interface page for that address. The CLI and the Python client add `/api` themselves, so `INFRAHUB_SYNC_API_URL` keeps its value, and a value that already ends in `/api` is accepted and not given a second `/api`. Upgrade and roll back the CLI and the service together: an older CLI against the new service prints `error: compatibility` with no server version, and the new CLI against an address that does not answer as a Sync API prints `error: not-a-sync-api` with the address it called. A script that calls the Sync API directly adds `/api` to its addresses. The operation that the service records for a refused token now starts with `/api`. The web interface no longer displays the actor of the token, and its development server no longer adds a token to the requests it forwards.
