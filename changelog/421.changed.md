The Sync API now serves the web interface at the root of its address, and every Sync API route has moved under `/api`, for example `/api/runs` and `/api/version`. The old paths at the root are not kept as aliases. The `infrahub-sync` CLI and the Python client keep `INFRAHUB_SYNC_API_URL` set to the address without `/api` and add the prefix themselves, so they need no change. The health checks in both compose files request `/api/version`. A health check, probe or script that calls the Sync API directly must move to `/api/version`, `/api/status` or the other `/api` paths. The request paths recorded in the audit history now start with `/api`. Rolling back to an earlier image requires moving those scripts and health checks back to the old paths. The released image contains the built web interface; the Python package does not. The new setting `INFRAHUB_SYNC_SERVICE_ANONYMOUS_ACTOR` lets requests without a token act as one principal from `INFRAHUB_SYNC_SERVICE_BEARER_TOKENS`, from the host names in `INFRAHUB_SYNC_SERVICE_ANONYMOUS_HOSTS` (by default `localhost`, `127.0.0.1` and `::1`) and from the same origin only. Without it, the web interface asks for a bearer token and keeps it in the browser until **Forget token**.
