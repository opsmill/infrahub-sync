The Infrahub adapter now asks the server for a node's identifier fields as well as its attribute fields, so objects keep the values they are keyed on even when the server returns only the fields the query named. A missing or null identifier now raises `PeerIdentifierError` naming the field, where conversion previously raised `AttributeError` or attempted a lookup using `None`; a missing non-identifier attribute still raises an error. Naming a relationship's identifier fields also fetches that peer's data; this adds some query cost that has not been measured.
