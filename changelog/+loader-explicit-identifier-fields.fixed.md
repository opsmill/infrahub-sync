The Infrahub adapter now requests identifier fields alongside attributes, so objects keep their keys when the server returns only requested fields. A loaded record or relationship peer with a missing or null identifier now raises a named error; with `--continue-on-error`, it is skipped with a warning instead of aborting the run, which previously failed with `AttributeError` for an absent record identifier. A missing non-identifier attribute still raises an error. Requesting relationship identifiers also fetches peer data, with unmeasured query cost.
