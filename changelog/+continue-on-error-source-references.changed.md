A source record that references a peer the read did not find when it read the record is no longer written with the relationship silently absent: `plan` lists a `peer_not_found_in_source` problem that names the referring field and the peer's kind and source ID, leaves the record and its dependents out when the relationship is required, and keeps the record without that relationship when it is optional (`infrahub-sync runs plan <run_id> --problems` and `--kept`). A parent of the same kind is found wherever the source lists it, but a peer of another kind that is read later, for example because of a configured `order`, is still reported this way.
