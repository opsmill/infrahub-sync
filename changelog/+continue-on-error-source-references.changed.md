A source record that references a peer the source does not return is no longer written with the relationship silently absent. `plan` lists it as a `peer_not_found_in_source` problem that names the referring field and the peer's kind and source ID; `sync` records the same problem in its saved plan, which `infrahub-sync runs plan <run_id> --problems` lists. When the relationship is required, the plan leaves the record out, and every record that depends on it; when the relationship is optional, the plan writes the record without that relationship and lists it among the kept records (`infrahub-sync runs plan <run_id> --kept`). The rest of the plan is planned as before. To write the relationship, add the peer's kind to the registered configuration so it is loaded, or remove the relationship from the schema mapping.
