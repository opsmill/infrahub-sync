`configs validate --branch` now judges `identifiers` by the rule the plan applies: when every human-friendly ID component of a kind can be written, `identifiers` must name all of them, or validation reports `destination-schema-mismatch` at `/configuration/schema_mapping/<n>/identifiers` and names the missing components. A package that passed validation before can now report this finding; add the missing fields to `identifiers` and register a new version. The destination schema fingerprint now includes the choices of each mapped Dropdown attribute, so the fingerprint of a configuration that maps one changes once, without a schema change. See "Upgrade from the V3 alpha" in the operations docs.
