The failure record of a failed run (`results.<stage>_failure` in `GET /runs/{run_id}` and `GET /runs/{run_id}/results`) now holds a `failure_type` and the fields of its cause: the system involved (`source` or `destination` and the adapter name), Infrahub's error code, node kind, attribute and own message for a rejected write, the record and field a load or transform failure names, and, for a stopped apply, the operation count of the plan and the action, kind and identity of the failed operation. `plan`, `verify`, `apply`, `sync` and `runs show` print these fields between `<stage> failed:` and `hint:`; `verify` now prints the failure record too. The record never holds the text of any other error, so no credential reaches it whatever its length (ADR 0021). The keys the record held before keep their values, and a record written by an older Sync API prints as before.
