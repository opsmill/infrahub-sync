The Sync service worker now starts only flow runs of the service's own deployment, exactly as the service applies it: the installed service entrypoint, no pull steps, no job variables on the deployment or the flow run, and the process work pool's default job template. Any other flow run in the work pool is marked `Crashed` with a fixed reason, and no process is started for it.

The Compose deployment now requires basic authentication on the Prefect API. Set `INFRAHUB_SYNC_PREFECT_AUTH_STRING` in `.env`; the Sync API, the worker and the bootstrap job present it, and Compose refuses to start without it. The Prefect UI at `http://127.0.0.1:4200` asks for a password once per browser: enter the whole value of `INFRAHUB_SYNC_PREFECT_AUTH_STRING`. After adding it to an existing deployment, run `docker compose up -d --wait`; `docker compose restart` keeps the old container environment.

The development stacks under `development/` now publish every port on `127.0.0.1` only, including the preview stack's PostgreSQL, MinIO, Prefect and Infrahub. On Linux, a Sync worker container that reads the preview Infrahub through `host.docker.internal` needs `PREVIEW_INFRAHUB_BIND_ADDRESS` set to the Docker bridge gateway in `development/preview.local.env`.
