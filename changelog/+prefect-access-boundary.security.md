The Sync service worker now starts only flow runs of the service's own deployment, exactly as the service applies it: the installed service entrypoint, no pull steps, no job variables on the deployment or the flow run, and the process work pool's default job template. Any other flow run in the work pool is marked `Crashed` with a fixed reason, and no process is started for it.

The Sync API, the worker and the bootstrap job present a Prefect API credential when `INFRAHUB_SYNC_PREFECT_AUTH_STRING` is set in `.env`. Infrahub's task manager offers no credential of its own, so without one, network isolation is the task manager's only protection; the API and the worker log which mode they run in.

The development stacks under `development/` now publish every port on `127.0.0.1` only, including the preview stack's PostgreSQL, MinIO, task manager and Infrahub. On Linux, a Sync worker container that reads the preview Infrahub through `host.docker.internal` needs `PREVIEW_INFRAHUB_BIND_ADDRESS` set to the Docker bridge gateway in `development/preview.local.env`.
