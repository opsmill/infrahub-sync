`SyncClient` is the supported Python interface for the Sync HTTP API. It sends typed requests to
the service and returns typed resources. It does not open a product store, load an adapter, resolve
execution credentials, or run the execution core in the caller process.

The base `infrahub-sync` installation includes the client and HTTPX. FastAPI, Uvicorn, Prefect,
Psycopg, and Boto3 remain optional service dependencies.

## Connect

Construct a client with the address of the Sync service, a bearer token, and a positive request
timeout. The address is an HTTP or HTTPS URL, for example `http://127.0.0.1:8001`. The client adds
`/api` to every request; an address that already ends in `/api` is accepted and not given a second `/api`.
`SyncClient.service_url` returns the address without `/api`. TLS verification is enabled and
redirects are refused.

HTTP provides no transport encryption for bearer credentials. Use HTTP only when the service
connection stays inside a network you trust; use HTTPS across networks you do not trust.

```python
from infrahub_sync.client import SyncClient

client = SyncClient("https://sync.example.com", "replace-with-a-token", timeout=30)
```

`SyncClient.from_environment()` reads `INFRAHUB_SYNC_API_URL` and
`INFRAHUB_SYNC_API_TOKEN`:

```python
from infrahub_sync.client import SyncClient

with SyncClient.from_environment(timeout=30) as client:
    version = client.get_version()
    health = client.get_health()
```

The first protected operation checks `/version` before sending the bearer token. The client
requires the server to declare `v3-unstable` and caches a successful compatibility check for that
client instance.

`get_health()` reads `GET /api/health` without a token. It returns a `HealthResource` for both a
`200` and a `503` answer, so read `health.status` (`healthy` or `unhealthy`), `health.dependencies`
and `health.workers` to find the cause. A `503` that carries an error envelope instead of a report
raises `APIError`; any other answer raises `ProtocolError`. See
[`GET /health`](./sync-http-api.mdx#get-health) for every field.

## Register and inspect configurations

Configuration mutations require an idempotency key. A reason is optional; when given, it is
recorded in the audit history. A retry after an uncertain transport result must reuse the same
key.

```python
from infrahub_sync.client import ConfigMutationRequest, SyncClient

package = {
    "format_version": 1,
    "configuration": {
        "name": "inventory",
        "source": {"name": "netbox", "settings": {}},
        "destination": {"name": "infrahub", "settings": {}},
    },
}

with SyncClient.from_environment() as client:
    registered = client.register_config(
        ConfigMutationRequest(package=package, reason="Register inventory sync"),
        idempotency_key="register-inventory-20260830",
    )
    config_id = registered.configuration.config_id
    registry_version = registered.version.registry_version
    report = client.validate_config(config_id, registry_version, offset=0, limit=256)
```

`package` above is a minimal shape: it registers, but without `schema_mapping` it
synchronizes nothing. For a complete package, see
`examples/netbox_to_infrahub/package.yml`.

The client also exposes `create_config_version`, `list_configs`, `get_config`,
`list_config_versions`, and `get_config_version`. Configuration list methods return the complete
server response and do not expose pagination arguments. Validation exposes the server's finding
page fields and preserves finding order. `check_package` takes a `PackageCheckRequest` with
`package` or `document` and validates a package that is not registered; it needs an
administrator token.

## Create and inspect runs

Create a plan from a registered configuration version:

```python
from infrahub_sync.client import CreateRunRequest, SyncClient

with SyncClient.from_environment() as client:
    accepted = client.plan(
        CreateRunRequest(
            operation="plan",
            config_id=config_id,
            registry_version=registry_version,
            branch="main",
            confirm_writes=False,
            reason="Review inventory changes",
        ),
        idempotency_key="plan-inventory-20260830",
    )
    finished = client.wait_for_run(accepted, timeout=1800, poll_interval=2)
    saved_plan = client.get_plan(finished.run.run_id)
```

A confirmed composed sync uses `operation="sync"` and `confirm_writes=True`. The client also
exposes `get_run`, `get_results`, `list_artifacts`, `get_artifact`, `verify_run`, `apply_run`, and
`cancel_run`. The short method names `sync`, `verify`, and `apply` call the same HTTP operations.

`apply_run` sends the expected checksum from the reviewed `PlanResource`. It does not read or
reconstruct plan bytes locally. `get_artifact` verifies the response `Digest` header against the
received bytes before returning `ArtifactContent`.

## Manage stored credentials

A configuration package names a [stored credential](../guides/credentials.mdx) with
`credential: <name>` in each adapter block that uses authentication. The client manages stored credentials with the same operations
as `infrahub-sync credentials` and the "Credentials" page of the web interface. Every signed-in
account can list and view them. Creating, changing and deleting need an administrator token.

```python
import os

from infrahub_sync.client import APIError, SyncClient

with SyncClient.from_environment() as client:
    created = client.create_credential(
        "netbox-token",
        token=os.environ["NETBOX_TOKEN"],
        description="NetBox lab, read-only token",
    )
    changed = client.set_credential_value("netbox-token", token=os.environ["NETBOX_TOKEN"])
    assert changed.revision == created.revision + 1

    for credential in client.iter_credentials():
        print(credential.name, credential.fields, credential.revision)

    try:
        client.delete_credential("netbox-token")
    except APIError as error:
        if error.code != "credential-in-use":
            raise
        print(error.configurations, error.schedules)
```

| Method | Command | What it does |
| --- | --- | --- |
| `list_credentials`, `iter_credentials` | `credentials list` | Returns one page, or every stored credential, sorted by name |
| `get_credential` | `credentials show NAME` | Returns one stored credential |
| `create_credential` | `credentials create NAME` | Creates a stored credential with its first value |
| `set_credential_value` | `credentials set NAME` | Replaces every field of the value; the revision goes up by one |
| `set_credential_description` | `credentials describe NAME TEXT` | Replaces the description; the revision stays |
| `delete_credential` | `credentials delete NAME` | Deletes the stored credential; this cannot be reversed |

A value is one of three sets of fields: `token`; `username` and `password`; `username` and
`token`. The client sends each value as given, in the request body only. No method returns a
value: a `CredentialResource` holds the names of the fields, the revision, and the accounts
and times of the creation and of the last change.

`delete_credential` raises `APIError` with the code `credential-in-use` while the latest version
of a configuration, or a schedule that is not deleted, names the credential. `configurations`
and `schedules` of the error list them.

## Wait behavior

`wait_for_run` follows the final orchestration entry in the accepted mutation response by its
`flow_run_id`. Earlier completed plan or verification executions do not make a later apply appear
complete. Unknown non-terminal live states continue polling until the bounded deadline.

The durable terminal outcome decides the result:

- completed/succeeded returns the latest `RunResource`;
- failed, cancelled, abandoned, or ambiguous outcomes raise `RunTerminalError`;
- reaching the deadline raises `RunWaitTimeoutError` with the run ID and last observed product and
  execution state.

A local `KeyboardInterrupt` stops the wait and crosses the Python boundary unchanged. It does not
cancel the remote run.

## Errors

Catch `SyncClientError` for all client-owned failures. More specific types are available for input,
compatibility, transport, protocol, API refusal, configuration API refusal, wait timeout, and
terminal run failures.

`NotSyncAPIError` reports an address that does not answer as a Sync API, for example a web page,
a proxy error page, or an older Sync service that does not serve `/api`. Its `operation`, `url`
(without query string) and `status` fields name the request; the response body is not kept.

```python
from infrahub_sync.client import ConfigsAPIError, SyncClientError

try:
    configurations = client.list_configs()
except ConfigsAPIError as exc:
    print(exc.status, exc.code, exc.family, exc.reason)
except SyncClientError:
    raise
```

Exceptions contain fixed client-owned text. Valid API refusals retain only their documented
machine fields. Raw response bodies, response headers, bearer values, and HTTPX exception chains
do not cross the client boundary.
