# `infrahub-sync`

Synchronize registered configurations through the Sync API.

Set `INFRAHUB_SYNC_API_TOKEN` to the bearer token for your actor before running any
command; the CLI reads it from the environment and never accepts it as a flag. See
[Sync HTTP API — Configure principals](./sync-http-api.mdx#configure-principals) for how
tokens are issued.

When the Sync API address is missing or invalid, or the token is missing, a command prints
`error: client-input` and `argument: service_url` or `argument: token` on standard error,
then a `hint:` line. An address is invalid when it does not use `http` or `https`, has no
host, or carries a user name, a password, a query string or a fragment. For the address,
set `INFRAHUB_SYNC_API_URL` or pass `--api-url` with the absolute URL of the Sync API; for
the token, set `INFRAHUB_SYNC_API_TOKEN`. Other `client-input` errors print no `hint:` line.

**Usage**:

```console
$ infrahub-sync [OPTIONS] COMMAND [ARGS]...
```

**Options**:

* `--api-url <str>`: Absolute URL of the Sync API. Defaults to INFRAHUB_SYNC_API_URL.  [env var: INFRAHUB_SYNC_API_URL]
* `--verbosity <quiet|default|verbose>`: Log verbosity level.  [default: default]
* `-v, --verbose`: Shorthand for --verbosity verbose.
* `-q, --quiet`: Shorthand for --verbosity quiet.
* `--install-completion`: Install completion for the current shell.
* `--show-completion`: Show completion for the current shell, to copy it or customize the installation.
* `--help`: Show this message and exit.

## `infrahub-sync plan`

**Usage**:

```console
$ infrahub-sync plan [OPTIONS]
```

* `--version <int>`: Registered configuration version.  [required]
* `--reason <str>`: Optional audit reason for the plan.
* `--branch <str>`: Destination branch admitted by the Sync API.
* `--idempotency-key <str>`: Retry key.
* `--wait / --no-wait`: Wait for this run&#x27;s execution.  [default: wait]
* `--wait-timeout <float>`: Bounded wait in seconds.  [default: 1800.0]
* `--poll-interval <float>`: Poll interval in seconds.  [default: 2.0]
* `--help`: Show this message and exit.

## `infrahub-sync approve`

The run is in phase `planned`, or its write stopped part-way and it can be resumed: a site that
requires approval then approves it before `runs resume`, for example a `sync` run.

**Usage**:

```console

```

**Arguments**:

* `run_id`: Service-issued run ID whose saved plan was reviewed.  [required]

* `--help`: Show this message and exit.

### `infrahub-sync runs resume`

Resume an interrupted apply from the run&#x27;s saved position, after a `verify` passed.

The resume applies the rest of the run&#x27;s saved plan in a new execution on the same run. It writes
the plan&#x27;s values over every operation that `verify` reported as differing from the plan.

**Usage**:

```console
$ infrahub-sync runs resume [OPTIONS] {run_id}
```

**Arguments**:

* `run_id`: Service-issued run ID whose write was interrupted.  [required]

**Options**:

* `--expected-checksum <str>`: Checksum printed by `runs plan`.  [required]
* `--confirm-left-out`: Confirm that you reviewed the records the plan leaves out; required when it leaves out any.
* `--reason <str>`: Optional audit reason for the resume.
* `--idempotency-key <str>`: Retry key.
* `--wait / --no-wait`: Wait for this run&#x27;s resume execution.  [default: wait]
* `--wait-timeout <float>`: Bounded wait in seconds.  [default: 1800.0]
* `--poll-interval <float>`: Poll interval in seconds.  [default: 2.0]
* `--help`: Show this message and exit.

### `infrahub-sync runs show`

Show one run&#x27;s service record and its selected execution.

`prefect_flow_run_url` links the flow run in the Prefect UI; it reads &lt;none&gt; when the Sync API has no UI address.
For a run with a `plan` or `sync` stage, `source_read` and `destination_read` show the read state of each side
in that stage&#x27;s latest execution: `state`, `mode`, `started_at`, `ended_at`, `nodes` and `error`, without the
keys that have no value. A side with no read state to return reads &lt;none&gt;. Neither line is printed when that
execution has no read state: a run recorded before the read state, a stage the worker has not started, or a
stage whose read state the worker could not store.
A failed stage adds its error type and, when the run recorded them, a `cause:` and a `hint:` line.
A `sync` that stopped after a plan that leaves out records adds a `sync stopped:` and a `hint:` line.
A run with a write adds a `progress:` line, a `resumable:` line, one `kind` line per kind with its committed,
uncertain and not reached operations, and one `resume` line per resume of the run. The counts are over the
plan&#x27;s positions, recorded deletes included. The uncertain operations follow the saved position: through the
failed operation when the worker recorded it, and every remaining operation when the worker was killed or its
last save is not known to have succeeded. While a resume runs, they are the next 500 creates and updates
and the recorded deletes between them; while a first apply or `sync` runs, none are uncertain. A `resume`
line counts the creates and updates that resume wrote; the `written:` line of a failed write counts those of
every execution of the run.

**Usage**:

```console
$ infrahub-sync runs show [OPTIONS] {run_id}
```

**Arguments**:

* `run_id`: Service-issued run ID.  [required]

**Options**:

* `--help`: Show this message and exit.

### `infrahub-sync runs plan`

Review a saved plan summary, checksum, and operations, or list its problems, left-out or kept records.

**Usage**:

```console
$ infrahub-sync runs plan [OPTIONS] {run_id}
```

**Arguments**:

* `run_id`: Service-issued run ID.  [required]

**Options**:

* `--detail`: Render every saved operation.
* `--kind <str>`: Filter the detailed operation list, or the problem, left-out or kept list, by destination kind.
* `--problems`: List every problem the plan found.
* `--left-out`: List every record the plan leaves out.
* `--kept`: List every record the plan keeps without one optional relationship.
* `--type <str>`: List only the problems of this problem type; requires --problems.
* `--help`: Show this message and exit.

### `infrahub-sync runs logs`

Print the lines Sync wrote during one run, oldest first: time, stage, level, message.

**Usage**:

```console
$ infrahub-sync runs logs [OPTIONS] {run_id}
```

**Arguments**:

* `run_id`: Service-issued run ID.  [required]

**Options**:

* `--stage <str>`: Only lines of this stage: plan, verify, apply, sync, resume.
* `--follow`: Read new lines every 2 seconds until the run ends.
* `--help`: Show this message and exit.
