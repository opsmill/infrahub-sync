---
title: Start a Compose deployment
---

Start Infrahub Sync from a release in three steps: fetch `docker-compose.yml`,
write a `.env` beside it, and start it. The deployment includes the Sync API,
worker, and object storage, and runs next to an Infrahub that ships Prefect 3.8.6
(1.11.3 or 1.11.4), started with Docker Compose on the same host: Sync uses
Infrahub's task manager and keeps its own database on the task manager's PostgreSQL
server. You can start it before you have supplied a source, destination,
configuration, or source credentials. This page ends when a worker reports `ready`
and you choose a source tutorial.

## Before you start

Review [Supported platforms and limits](./operations/supported-platforms-and-limits.mdx)
before you start. Install Docker and Docker Compose on the deployment host, then
check it:

```sh
uname -s
uname -m
docker compose version --short
```

Expect `Linux`, `x86_64` or `aarch64`, and Docker Compose 2.24 or later. On
another platform, see
[Supported platforms and limits](./operations/supported-platforms-and-limits.mdx#other-platforms-including-apple-silicon).

Until the 3.0.0 release, the image registry is open to invited testers only. Log
in before the first start, as described in
[Install Infrahub Sync](./installation.mdx#run-the-container-image):

```sh
docker login registry.opsmill.io
```

Port 8000 on `127.0.0.1` must be available, and Infrahub must be running. Docker needs registry
access to pull the service images, and enough space for the images and the
persistent deployment data.

Run the remaining commands on the Docker host. For a remote host, connect
through SSH.

## Get the file

Create a directory for the deployment and fetch `docker-compose.yml` from the
release tag you want, for example `3.0.0`:

```sh
mkdir infrahub-sync && cd infrahub-sync
curl -fsSLO https://raw.githubusercontent.com/opsmill/infrahub-sync/<version>/docker-compose.yml
```

The file pins the Sync image of that release. Run every later command from this
directory.

## Write the credentials

The file needs five credentials, and defaults none of them. This generates random
values for Sync's own credentials, takes the task-manager database password from the
`INFRAHUB_TASKMANAGER_DB_PASSWORD` variable of your shell and falls back to
`postgres`, Infrahub's default, and gives the bundled CLI the same token as the one
principal the API accepts. If you started Infrahub with another password, for
example from Infrahub's own `.env`, export `INFRAHUB_TASKMANAGER_DB_PASSWORD` with
that value before you run it; otherwise `db-bootstrap` cannot authenticate against
`task-manager-db`.

```sh
rand() { od -An -tx1 -N"$1" /dev/urandom | tr -d ' \n'; }
principal=$(rand 24)
# mktemp creates the file readable by you alone, whatever an existing .env allowed.
env_file=$(mktemp .env.XXXXXX)
cat > "$env_file" <<EOF
INFRAHUB_TASKMANAGER_DB_PASSWORD=${INFRAHUB_TASKMANAGER_DB_PASSWORD:-postgres}
INFRAHUB_SYNC_PRODUCT_PASSWORD=$(rand 24)
INFRAHUB_SYNC_S3_ACCESS_KEY=$(rand 12)
INFRAHUB_SYNC_S3_SECRET_KEY=$(rand 24)
INFRAHUB_SYNC_SERVICE_BEARER_TOKENS={"operator": {"token": "$principal", "administrator": true}}
INFRAHUB_SYNC_API_TOKEN=$principal
EOF
mv -f "$env_file" .env
docker compose config --quiet
```

`config --quiet` prints nothing when every credential is set. Otherwise it names
the missing one, for example `INFRAHUB_SYNC_PRODUCT_PASSWORD is required`. Keep
`.env` out of version control and never `source` it. Every variable it can set,
including the image version, is listed in
[The `.env` file](./compose-deployment.mdx#configuration-prerequisites).

## Start the deployment

```sh
docker compose up -d --wait
curl -s http://127.0.0.1:8000/status
```

`up -d --wait` pulls the images and returns once every service is healthy. In the
`/status` response, `worker.state` must be `ready`. If it reads `no-live-worker`,
wait a few seconds and repeat the request. If `up` fails, see
[Compose operator troubleshooting](./operations/compose-troubleshooting.mdx).

A `ready` worker confirms the deployment is running; it does not check a source or
destination.

## Identify your installed version

```sh
curl --fail --silent --show-error http://127.0.0.1:8000/version
```

The response shows `server_version`. If you changed the API port, use that port
in the URL. Include this version when reporting feedback through your usual
company channel.

## Moving from an older version

An earlier alpha deployed through the `infrahub-sync-compose` wrapper. Start the new
release in a new directory with a new `.env`, and empty state. If the old
deployment uses the same ports, stop it first and keep its directory and volumes.
Do not point the new deployment at the old data. Supply credentials in the new
`.env`, register your configuration again, and review a fresh plan before
applying. The [wrapper equivalents](./compose-deployment.mdx#wrapper-equivalents)
map each old command to its `docker compose` form.

This release has no in-place state migration or verified rollback procedure. It
does not move or clean up objects an older version created in your destination.
