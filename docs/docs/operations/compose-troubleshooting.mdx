title: Compose operator troubleshooting

Diagnose a Compose deployment on one Docker host. For the local stacks that run from
source, see [Local development stack](../development-stack.mdx). For the NetBox demo
tutorial, see its [Troubleshooting](../tutorials/netbox-demo-to-infrahub#troubleshooting)
section.

## Start with the deployment state

Run the [status procedure](../compose-deployment#status) first: `docker compose ps`,
then the worker state from `/status`.

Use the [log procedure](../compose-deployment#logs) to read service output. Credentials
are removed from run failures before they are printed.

If a configuration validation reports a finding, use its stable code to find the
meaning in the [finding-code reference](../reference/durable-product-records#finding-codes).
The message wording can change; the code stays the same.

## Failures before the start

| Symptom | Cause and action |
| --- | --- |
| Compose fails to parse `configs.db-bootstrap-script.content` | Compose is older than 2.24. Upgrade it; check with `docker compose version --short`. |
| `<NAME> is required` | A required credential is missing from `.env`. Compose prints this before any container starts, from `docker compose config --quiet` or `up`. Add the named variable. |
| A pull error naming `registry.opsmill.io/opsmill/infrahub-sync:<version>` | The image cannot be pulled. Check `docker login registry.opsmill.io`, which is needed until 3.0.0, then `VERSION` and `INFRAHUB_SYNC_DOCKER_IMAGE`. See [Choose an image](../compose-deployment#choose-an-image). |
| `up` fails on a port publication | Another process holds the port. Set `INFRAHUB_SYNC_API_PORT` in `.env`. |
| The services run an unexpected image | A `VERSION` or `INFRAHUB_SYNC_DOCKER_IMAGE` exported in your shell overrides `.env`. Unset it, then run `docker compose up -d --wait`. |

## Failures after the start

| Symptom | Action |
| --- | --- |
| No container is running | Run `docker compose up -d --wait`. |
| `sync-api` or `sync-worker` restarts in a loop and the log says the Sync schema is missing | Infrahub lacks Sync's schema extension, or holds an older one. Load it with `infrahubctl schema load schema/sync.yml` (on a branch, then merge), then run `docker compose up -d --wait`. |
| `sync-api` or `sync-worker` restarts in a loop and the log says Infrahub refused `INFRAHUB_SYNC_INFRAHUB_TOKEN` | The service account's token is wrong, expired or revoked. Create a token for the Sync service account in Infrahub, set it in `.env`, then run `docker compose up -d --wait`. |
| Every authenticated call answers `503 identity-unavailable` | The API cannot reach Infrahub at `INFRAHUB_SYNC_INFRAHUB_ADDRESS`. Check that Infrahub is up and that `INFRAHUB_NETWORK` names its Compose network. |
| `worker.state` is `no-live-worker` | Read the worker logs, then run `docker compose restart sync-api sync-worker`. It keeps the durable records. A paused or hung worker still looks `running` to Docker; only the worker state shows it, after three missed heartbeats or 30 seconds. |
| A changed `.env` value has no effect | A container reads its environment once, when it is created. Run `docker compose up -d --wait`, not `restart`. |
| You want to delete all data and begin again | Follow the [replacement procedure](../compose-deployment#resetting-this-alpha-to-a-fresh-deployment). Dropping Sync's database cannot be undone. |

The [stop, restart, and reset procedure](../compose-deployment#stop-restart-and-reset)
describes each action. A reset followed by a fresh deployment is not an upgrade: the new
deployment starts empty.

## Command-line client failures

`docker compose run --rm --no-deps -T cli ...` calls the Sync API with your own Infrahub
API token, `INFRAHUB_SYNC_TOKEN`.

- **Every call prints `error: client-input` and `argument: token`, and exits with status
  `2`.** `INFRAHUB_SYNC_TOKEN` is empty, so the client stops before it calls the API.
  Export your Infrahub API token in your shell, then run the command again.
- **Every call answers `401`.** Infrahub refuses the token: it is expired or revoked, or
  its account is inactive. Export a valid Infrahub API token in your shell, then run the
  command again.
- **A call answers `403`.** Your Infrahub account lacks the permission that the message
  names, for example `object:Sync:Approval:create`. Ask an Infrahub administrator to grant
  it on the default branch; see
  [Caller permissions](../compose-deployment#caller-permissions).
- **Every call answers `503 identity-unavailable`.** The Sync API cannot reach Infrahub to
  ask who you are. Check `INFRAHUB_SYNC_INFRAHUB_ADDRESS` and that Infrahub is running.
- **`configs register` or `configs version` answers `410 configurations-in-infrahub`.**
  Configurations live in Infrahub. Create or edit the `SyncConfiguration` there; the next
  run records the version. See
  [Create the configuration in Infrahub](../compose-deployment#create-the-configuration-in-infrahub).
- **An `.env` from an earlier alpha still sets `INFRAHUB_SYNC_SERVICE_BEARER_TOKENS` and
  `INFRAHUB_SYNC_API_TOKEN`.** The Sync API no longer reads either. Remove
  `INFRAHUB_SYNC_SERVICE_BEARER_TOKENS`, add `INFRAHUB_SYNC_INFRAHUB_TOKEN` with the Sync
  service account's token, and call the CLI with your own token in `INFRAHUB_SYNC_TOKEN`.
  The CLI still reads `INFRAHUB_SYNC_API_TOKEN` when `INFRAHUB_SYNC_TOKEN` is unset, but
  the Compose `cli` service passes only `INFRAHUB_SYNC_TOKEN`.

## Reconcile before retrying writes

When a write might have reached the destination, do not repeat it. Follow the
[uncertain-write reconciliation procedure](../compose-deployment#when-the-outcome-of-a-write-is-uncertain):
read the run record, inspect the destination, and create a fresh plan.
