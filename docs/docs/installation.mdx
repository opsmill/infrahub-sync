---
title: Install Infrahub Sync
---

Infrahub Sync V3 runs as a service. The service includes the Sync API, a worker,
Prefect, PostgreSQL, and object storage. You use the `infrahub-sync`
command-line client to send requests to the Sync API.

**Moving from V2?** [Move from V2 to V3](./v2-to-v3.mdx) compares the two lines and states
what to prepare first. A switch starts a fresh deployment; there is no in-place state
migration. The [PyPI package](https://pypi.org/project/infrahub-sync/) holds both lines:
versions 2.x are V2, and versions 3.0.0 and later are V3.

## Two ways to run V3

- **Run from source** — to try the latest changes. Build and start the service from a
  checkout of `feature/v3-develop`, on any platform Docker supports, including Apple
  Silicon.
- **Run the container image** — to run a fixed release. Every release publishes a
  signed image for Linux amd64 and arm64 to the OpsMill registry.

Both run the same Sync service.

| | Run from source | Run the container image |
| --- | --- | --- |
| You need | Docker, Git, [uv](https://docs.astral.sh/uv/), and Python 3.11 to 3.13 | Docker with Docker Compose, and an existing NetBox or Nautobot and Infrahub that the Sync worker can reach |
| Start here | [Run from source](./development-stack.mdx#run-from-source) | [Run the container image](#run-the-container-image) below |

See [Supported platforms and limits](./operations/supported-platforms-and-limits.mdx)
for the current product limits.

## Run the container image {#run-the-container-image}

The image lives at `registry.opsmill.io/opsmill/infrahub-sync`, tagged with each
release's version. Until the 3.0.0 release, the registry is open to invited testers
only, so run `docker login registry.opsmill.io` before you pull.

- [Container image](./container-image.mdx) covers the tags, the supported platforms,
  pulling, and checking the image's signature and bills of materials.
- [Compose deployment](./compose-deployment.mdx) runs the full service from that
  image: the Sync API, the worker, Prefect, PostgreSQL, and object storage.

## Install the CLI {#install-the-cli}

You run the `infrahub-sync` CLI on any machine that can reach the Sync API, such as your
workstation, a CI runner, or the Docker host. The CLI is published on
[PyPI](https://pypi.org/project/infrahub-sync/) and needs Python 3.10 to 3.13. Install a
3.x version, because the 2.x versions are V2.

The commands below install from PyPI once version 3.0.0 is published there. Until
then, PyPI has no 3.x version, so run the CLI through the Compose deployment's `cli`
service instead. From the directory that holds `.env`, run
`docker compose run --rm --no-deps -T cli <command>`, for example
`docker compose run --rm --no-deps -T cli configs list`. See
[Use it](./compose-deployment.mdx#use-it) in the Compose deployment guide.

To install the CLI with uv:

```bash
uv tool install "infrahub-sync>=3,<4"
```

To install it with pip instead, use a virtual environment:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install "infrahub-sync>=3,<4"
```

To use the same version as the image your deployment runs, pin that version, for example
`infrahub-sync==3.0.0`.

Run `infrahub-sync configs --help` to confirm that you installed V3. V2 has no `configs`
command. Then [connect the CLI to the Sync API](./running-a-sync.mdx#connect-the-cli-to-the-sync-api).
