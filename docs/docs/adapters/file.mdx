The File adapter loads data from local file exports and synchronizes it into Infrahub. It is designed for the common case where another system can export flat files (CSV today) that you want to ingest without standing up an API integration.

The adapter is built around a small registry of file readers, so support for additional formats (JSON, YAML, Excel) can be added without changing the adapter logic.

## Key features

- Reads local CSV exports into Infrahub models
- File format inferred from the file extension, with an optional `format` override
- Configurable base directory, delimiter, and encoding
- Filtering and transformation support (shared with the other adapters)
- Scalar and list references to other models, resolved by identifier or `id` column

## Sync directions supported

- File → Infrahub

:::info

The File adapter currently supports only **one-way synchronization** from local files into Infrahub.
Writing data back to files is not yet supported: using `file` as a destination raises an error.

:::

## Supported formats

| Format | Extension | Status |
|--------|-----------|--------|
| CSV | `.csv` | Supported |
| JSON | `.json` | Planned |
| YAML | `.yml`, `.yaml` | Planned |
| Excel | `.xlsx` | Planned |

If a file uses an unrecognized extension, set the `format` setting explicitly. An unsupported format raises a clear error listing the formats that are available.

## Configuration

### Basic configuration

To use the File adapter, specify `file` as the source name and point the schema mapping at your exported files:

```yaml
source:
  name: file
  settings:
    directory: "data"
```

### Configuration parameters

| Parameter | Description | Default | Required |
|-----------|-------------|---------|----------|
| `directory` | Base directory used to resolve relative file paths. A relative value is resolved against the directory containing `config.yml` | Directory containing `config.yml` | No |
| `format` | Force a format instead of inferring from the extension (for example, `csv`) | Inferred from extension | No |
| `delimiter` | CSV field separator | `,` | No |
| `encoding` | File encoding. The default also strips the byte order mark that Excel writes | `utf-8-sig` | No |
| `empty_as_none` | Treat empty CSV cells as `null` instead of `""` | `true` | No |
| `list_separator` | Separator used to split list/reference fields. Must not be empty | `;` | No |

## Schema mapping

The `mapping` key of each schema mapping entry is the file to read, interpreted relative to the configured `directory` (or as an absolute path):

```yaml
order:
  - OrganizationGeneric
  - InfraDevice

schema_mapping:
  - name: OrganizationGeneric
    mapping: organizations.csv
    identifiers: ["name"]
    fields:
      - name: name
        mapping: name
      - name: description
        mapping: description

  - name: InfraDevice
    mapping: devices.csv
    identifiers: ["name"]
    fields:
      - name: name
        mapping: name
      - name: organization
        mapping: organization
        reference: OrganizationGeneric
```

### Field mapping types

- **Direct mapping**: Maps a column to an Infrahub field.
- **Static value**: Sets a constant value for an Infrahub field. Values such as `0`, `false`, or an empty string are applied too.
- **Reference**: Links to another Infrahub model. For flat files the referenced column holds either the target object's identifier (for example, the organization name) or the value of the target file's `id` column. For a target with several identifiers, join their values with `__` (for example, `dc1__emea`). The referenced model must be defined in `schema_mapping` and loaded before this one in `order`; a value that matches no loaded object raises an error.

Every schema mapping entry must define at least one field.

### List and reference values

A column that maps to a list attribute (or a list reference) is split using `list_separator` (default `;`). For example, an `aliases` column with the value `core;edge` becomes `["core", "edge"]`.

### Identifiers

Objects are matched with the destination by the model's identifiers. The adapter also keeps a source-local identifier for each row, used to resolve references: the row's `id` column when the file has one, otherwise the identifier values joined with `__`. Columns ending in `_id` are not used, because in flat exports they usually hold foreign keys.

### Duplicate rows

Rows that produce the same identifier are loaded once, keeping the first occurrence. This is expected when a model is derived from a foreign-key column, such as organizations taken from the `organization` column of a device export. When the repeated rows carry different values, the adapter logs a warning naming the identifier so the discarded data is visible.

## Example data

Given `organizations.csv`:

```csv
name,description
Acme,Acme headquarters
Globex,Globex regional office
```

and `devices.csv`:

```csv
name,description,organization
device-001,Core router,Acme
device-002,Access switch,Acme
```

the `organization` column on each device resolves to the matching `OrganizationGeneric` object.

## Common errors

| Error | Cause | Resolution |
|-------|-------|------------|
| `File not found: ...` | The mapped file does not exist relative to `directory` | Check the `directory` setting and the `mapping` path |
| `Unsupported file format for ...` | The extension is not recognized and no `format` is set | Use a `.csv` file or set the `format` setting |
| `Error reading data from ...` | The file could not be parsed (for example, malformed CSV) | Verify the delimiter, encoding, and file contents |
| `Duplicate column(s) in header ...` | Two columns share a name, so one would silently overwrite the other | Rename or remove the repeated column |
| `Line N ... has more cells than the header` | A row has non-empty values beyond the last header column | Fix the row, or check that `delimiter` matches the file |
| `Unable to resolve '...' for field ...` | A reference value matches no loaded object | Check the value, and that the referenced model comes earlier in `order` |
| `... which is not defined in schema_mapping` | A `reference` names a model with no schema mapping entry | Fix the model name in `reference` |
| `No fields defined in schema mapping ...` | A schema mapping entry has an empty `fields` list | Add at least the identifier fields |
